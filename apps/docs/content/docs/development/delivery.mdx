The product manual deploys independently at `docs.chardesk.com`; the
[docs workspace contract](https://github.com/Sayhi-bzb/CharDesk/blob/main/apps/docs/README.md)
owns its two build targets and deployment. Existing engineering Agent resources
remain under the main site's `/docs`; old human URLs have explicit migration
destinations. Canvas deploys from `apps/canvas/dist`, while
[main-site assembly](https://github.com/Sayhi-bzb/CharDesk/blob/main/apps/site/README.md)
owns `apps/site/dist` and the legacy workspace bridge.

## Documentation freshness

`apps/docs/content/docs-head.json` is the committed source revision against which
the whole documentation set was last reviewed.

1. Review committed changes after that revision plus the current worktree.
2. Route affected contracts through [Development](/development); update an owner
   route when a new contract has no destination.
3. Leave prose unchanged when implementation changes preserve the documented
   contract, but still count the page as reviewed.
4. After affected pages and emitted outputs pass verification, advance `head` to
   the full SHA of the reviewed commit.

A clean review may advance `head` without a prose change. Never record dirty or
worktree state, and never advance the baseline automatically during a build.

## Package releases

The [release workflow](https://github.com/Sayhi-bzb/CharDesk/blob/main/.github/workflows/release.yml)
prepares one release PR update daily, or manually on `main` with an empty `tag`.
Preparation requires a successful Verify of the latest main commit. The
[preparation action](https://github.com/Sayhi-bzb/CharDesk/tree/main/.github/actions/prepare-release)
uses a Release Please plugin to apply `release:sync` and `release:verify` before
writing the PR, including dependency ranges and registry output in the same commit.
Ordinary main pushes do not update the release branch. Preparation skips unchanged
release notes, including changes to the generated release date alone.

Merging a release PR still creates its tag and GitHub release only after Verify
passes. Manual dispatch with an existing `tag` on the matching tag ref retries
publication. [Release policy tests](https://github.com/Sayhi-bzb/CharDesk/blob/main/scripts/release/automation.test.mjs)
cover preparation and publication gates; [workspace tests](https://github.com/Sayhi-bzb/CharDesk/blob/main/scripts/release/prepare-workspace.test.mjs)
cover the combined update.

A release tag is stable SemVer shared by both package manifests and their lockfile
entries. Packed tarballs must pass installation, public export and font asset smoke
checks before publication. Reruns skip each package version already on npm and
replace assets on an existing GitHub release.
