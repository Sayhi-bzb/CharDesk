## Canonical flows

- Freeform content: command -> compact `CellPlanePatch` -> one ordered CellPlane
  operation in a Yjs transaction -> 128x64 spatial projection -> viewport query.
  Text runs remain compact through the write boundary; target-background inheritance
  is operation composition, not a per-cell read/modify/write pass.
- External rich-text paste: clipboard snapshot -> literal source with matching HTML
  semantic spans -> shared text compiler -> compact write boundary. Source text owns
  whitespace; HTML supplies styles only when its text matches. Implementation:
  [clipboard adapter](https://github.com/Sayhi-bzb/CharDesk/blob/main/apps/canvas/src/domains/actions/adapters/htmlClipboard.ts)
  and [semantic text](https://github.com/Sayhi-bzb/CharDesk/blob/main/packages/chargraph/src/semantic-text.ts).
  Verification: [clipboard tests](https://github.com/Sayhi-bzb/CharDesk/blob/main/apps/canvas/src/domains/actions/adapters/clipboardActions.dom.test.ts)
  and [wrap tests](https://github.com/Sayhi-bzb/CharDesk/blob/main/packages/chargraph/src/markdown-wrap.test.ts).
- Session activation: active ViewRuntime checkpoint -> catalog descriptor ->
  restored mode-authoritative Yjs document -> one editor-state activation patch.
  Content projection is already current; interaction resets against the newly
  active document/page address.
- Slide activation: deck metadata -> matching page in the session Yjs document -> active projection.
- Slide edit: command -> active Yjs page -> derived active grid.
- Local restore: IndexedDB catalog -> `y-indexeddb` document restore -> canvas recovery
  adapter -> active projection. Startup does not expose editing until the active document is ready.
- Canvas switch: retain the current frame -> load the target Yjs document -> commit the latest
  activation request -> release an unpinned least-recently-used document when over budget.
- Import: document parser -> `CanvasImportSnapshot` -> canvas session command ->
  one-shot active-pane camera placement. The placement uses projected content bounds
  and viewport insets at runtime; it is not part of the document protocol or persistence.
- Session persistence: metadata projection -> sessions catalog transaction. Canvas content
  remains in its Yjs document and persists as incremental `y-indexeddb` updates. A flush
  visits dirty documents only; routine edits never force workspace-wide snapshots.
- Viewport: pointer, keyboard, minimap, or zoom command -> active-view port ->
  live camera -> settled camera -> session saved viewport -> catalog persistence.
  `CanvasViewportRuntime` is the only active-camera authority; Zustand does not
  mirror its offset or zoom. Animation frames never write session metadata.
- Slide preview: deck metadata + page reader -> explicit grid snapshot -> canonical slide renderer.
- Selection command: Host input -> `editor-input` -> command registry ->
  canvas selection port -> Yjs document.
- Artifact appearance: stored Cell style -> canonical default-foreground classification ->
  active Canvas palette for visual projections or default SGR state for ANSI serialization.
  A stored background makes its foreground explicit; persistence retains literal colors.
- External text: [shared format selection and compilation](/development/architecture/text-rendering-pipeline)
  → Protocol rows → Canvas mutation.
- Local document preview: file → native document parser → read-only projection.
  Human commands cannot write back to the file.
- [WebMCP](/development/architecture/webmcp) composes Canvas read/search/write and shared Materials tools.
  [Canvas reading](/development/architecture/canvas-reading) exposes an automatically scaled Cell viewport.
